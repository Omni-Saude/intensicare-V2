# 04 — Product requirements (deliberately empty)

This directory is part of the §16 hierarchy but holds no requirement catalog
yet, **by design, not omission**.

**Why empty:** PRD/USR requirements must derive from validated user needs
(prompt §8). Gate G1 is NOT satisfied — no user has been observed; only
hypotheses exist (`docs/02-users-and-workflows/`), with 42 blocking items in
`docs/02-users-and-workflows/g1-validation-backlog.md`. Writing a requirement
catalog now would launder hypotheses into requirements.

**Known forward references:** the ADR drafts in `docs/06-architecture/adrs/`
carry unresolved `REQ:` placeholders that must be replaced with real PRD/USR
IDs when this directory is populated.

**Populated when:** Gate G1 passes (observed workflows + named intended-use
approver), after which the prioritized requirement catalog with stable IDs
(OUT/USR/PRD per `docs/00-governance/traceability-policy.md`) lands here.
